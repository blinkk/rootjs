# Themes

> **Experimental.** The CMS's markup changes as features are added, so a
> theme may need adjusting from version to version. The `--cms-*` custom
> properties are the part meant to last.

A theme is a stylesheet loaded after the CMS's own, so it can restyle
anything its CSS reaches.

## Writing one

Start from `packages/root-cms/ui/styles/theme.css`. It holds every custom
property the CMS reads, at its stock value, with a note on what each one
does (the same list is in the [reference](#reference) below). Copy the
properties you want to change into your theme's `:root` and change their
values:

```css
:root {
  --cms-accent: #4c6ef5;
  --cms-color-page: #f4f4f1;
  --cms-radius-md: 2px;
  --cms-drawer-border: 1px solid var(--cms-color-border);
}
```

Every Tailwind utility the UI uses (colors, radii, type sizes, shadows)
reads one of these properties, so a change restyles every component that
uses it.

When a property doesn't reach what you need, target a component's BEM hook
(see [what is stable](#what-is-stable)):

```css
.DocEditor__statusBar {
  background: var(--cms-color-surface-hover);
}
.Button--variant-primary {
  text-transform: uppercase;
}
```

Themes load unlayered, after the CMS's CSS (which sits in cascade layers),
so a plain selector in a theme beats the CMS's own rules and utilities
without extra specificity or `!important`.

## Registering them

Themes come from the project: a local file, or a package or plugin that
exports one. `cmsPlugin` takes the list and picks which applies by default:

```ts
cmsPlugin({
  themes: [
    {id: 'clarity', name: 'Clarity', file: './cms/clarity.css'},
    ...somePlugin.themes,
  ],
  defaultTheme: 'clarity',
});
```

- `id`: appears in the URL and in a user's preference; lowercase letters,
  digits and hyphens.
- `name`: shown in the picker. Defaults to the id.
- `file`: relative to the project root.
- `css`: a string instead of a file, or appended after one.

Each theme is served at `/cms/themes/<id>.css` behind the CMS's login and
read on each request, so an edit to the file shows on the next reload. The
link is cache-busted by the stylesheet's content.

## Choosing one

Every user picks their own theme under **Settings → Theme**, from the list
the project registered. "Default" is the CMS's own look; the theme the
project made its default is marked "(default)" and applies until the user
picks another. Without a `defaultTheme`, they get the CMS's own look.

## Custom CSS from the CMS

CSS can also be added without a deploy, under **Settings → Theme**:

- **Project CSS**: applies to everyone on the project (admins).
- **Personal CSS**: applies to you only.

Paste CSS directly, or pull in a hosted file with
`@import url("https://…");` (a stylesheet in a GitHub repo, served raw,
works). The cascade order is: base stylesheet, theme, site custom CSS, user
custom CSS; later wins.

## What is stable

- **`--cms-*` custom properties** are the supported surface. Their names and
  meanings are kept stable across releases, and a theme written only
  against them keeps working when the markup underneath changes.
- **BEM hooks** (the `Block`, `Block__element` and `Block--modifier` classes
  in the [reference](#reference)) are supported hooks. They're best effort:
  a rename or removal is called out in the changelog, so re-check a theme
  that uses them after an upgrade.
- **Everything else** (utility classes such as `px-3` or `bg-surface`,
  element nesting and order, ARIA attributes) is not supported and may
  change with any release.

Need a dial that isn't there? Add the property to `ui/styles/theme.css` with
the stock value, use it from the component's CSS or a utility (see
`ui/styles/tailwind.css`), and re-run the reference script below. That keeps
the contract honest rather than reaching for a class name.
